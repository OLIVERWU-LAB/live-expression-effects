# 性能红线与 ROI · v59

## 已落地的实现

- 礼物采用 Blender 离线渲染的 PNG 旋转图集，网页绘制精灵，不在浏览器逐物件计算三维网格、材质和灯光。旋转每次选取一个完整姿态，避免两个姿态透明混合导致 S 管、圆环重影。
- 当前只加载糖果与柔彩糖果两套材质；图集缓存最多两套。水滴图块、写实锥形头部与光点按需缓存，不逐粒子执行实时模糊。
- 最多 700 活动粒子、3 发升空烟花、150 段余光；低性能预算最低 150 粒子。单发写实初始 366 粒子。回收粒子时淡出，降级保留内圈、外圈和闪点结构。
- 主画布约 160 万像素上限，DPR 最高 1.35。预热 4 秒后，连续低帧率且实际绘制开销大时减少粒子；性能持续恢复时增加。后台限帧不当作设备过载。
- 人脸推理位于 Worker，一次只有一个在途帧。按耗时将间隔调整到 50–160 ms；人物分割至少间隔 180 ms，手部至少 90 ms。模型同源托管并缓存，图像不上传。
- 标签页隐藏时暂停视频与识别；待机首页不绘制特效。烟花到雨滴有 0.24 秒收尾，不等待整场烟花完全消失。

## 本次可验证的优化

1. 人物遮罩每帧由两次调用变为一次。人物分割遮罩本来有缓存；节省主要发生在模拟人物／无分割而使用多边形轮廓的路径。
2. 同一射线的高亮颜色只算一次，避免每段拖尾重复调色。
3. 主体验只走原版优化渲染分支，省去历史效果分组与临时数组。
4. 正式部署按依赖清单打包。完整 dist 约 59.5 MB，正式资源约 38.2 MB；礼物素材约 27.8 MB → 6.6 MB。均为文件原始字节，非网络压缩传输量；旧素材原先不会全被浏览器下载，因此部署体积减少不能直接等同于首屏加速。按 PNG 尺寸估算，两套礼物图集解码 RGBA 约 77.5 MB，浏览器/GPU 副本另计；不能用压缩文件大小代替内存预算。

同一台机器、固定种子与 366 粒子，交替运行前后各 800 次的 Node 绘制指令准备基准，v58 中位约 4.05 ms，v59 约 3.40 ms。该基准不包含光栅、GPU、摄像头与识别，不是浏览器帧率承诺。写实在 21 个时点逐像素一致；扁平首爆之后的粒子数据一致。

## ROI 判断与验收边界

当前固定镜头、小尺寸、短生命周期的礼物适合图集，代价是旋转视角有限。识别和碰撞响应优先于继续堆粒子；形态、大小差和时差优先于增加实时光照成本。缓存、预算和可重复回归能让每次视觉调整有明确成本。

尚需在目标中档手机上开启摄像头连续运行，测量整条链路的 p95 帧耗时、帧率、内存和温升，并与关闭特效的基线比较。题目未给出具体 FPS 红线，不能将本机测试写成所有设备通过。

## v63 末段火焰尾迹

仅在晚期对既有尾迹采样增加横向偏移与明暗包络；不改变碰撞坐标，也不新增粒子、尾迹采样或模糊纹理。固定场景 1.2 秒、637 活动粒子的 Node 绘制指令准备微基准，旧版中位约 3.46 ms，新版约 3.78 ms，额外约 0.32 ms。本机微基准不包含光栅、GPU、摄像头与识别；真实手机帧耗时仍需整体验证。
