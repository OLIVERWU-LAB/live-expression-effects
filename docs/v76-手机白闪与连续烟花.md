# v76 · 手机尾段绘制、连续烟花与首次点击

## 本轮变更

- 已逐帧读取用户的 1.71 秒手机录屏：尾段出现的是靠近人物的短白色楔状亮条，不是整页曝光变化。当前桌面 CPU 绘制不能复现 iOS GPU 的异常，因此不能把特定 WebKit 驱动故障视为已证实的根因。
- 针对长尾末段更换绘制路径：去掉短小、低透明度的线性渐变填充，使用最多 12 段显式彩色四边形，分别限定透明度；极低亮度尾段不再提交绘制。碰撞前景和遮挡路径结束时清空当前路径，避免跨层遗留路径。保留人物碰撞、内外圈结构和小白色亮点。
- 扁平主体模拟速度从 0.88 提至 1.14（约快 30%），升空从 0.58–0.68 秒缩到 0.46–0.56 秒。下一枚在上一组主体剩余不超过 1.20 模拟秒时即可升空。最低发射间隔 1.25 秒；不清空已有粒子、不改变散射方向或缩小花形。
- 修正普通低帧率时丢弃时间的问题：扁平每次绘制最多推进两段 50ms 的模拟；12–20 FPS 不再因时间截断而额外慢放。长时间中断仍截断，不积攒补帧队列。识别与绘制仍各运行一次，不提高模型调用频率。
- 底部表情条改为纯色：亮蓝 `#58D5FF`、粉紫 `#ED83FF`。
- 升空改成低音量、带柔和包络的程序滑音；主爆炸继续用用户的 Explode。关闭 Fireworks2 回声和 Shining；背景仅保留 Sparks，增益降到 0.030。礼物纸屑仍为程序声音。
- 人物水珠声改为短促、高频衰减的水滴共鸣，碰撞间隔至少 170ms；连续雨底声保持低音量。程序 PCM 缓存复用，无逐滴音源、播放计时器或音频主线程回调。
- 正式音频下载从四段减为 Explode、Sparks 两段。旧切片留在源码历史，不随正式站点传输。
- 开启摄像头：在应用模块下载前，用内联小脚本接住首次明确点击，当次手势内就请求摄像头，并显示「正在开启…」。主应用接管同一个请求，不二次弹权限、不等音效初始化。未点击不自动申请权限。浏览器／操作系统展示权限弹窗的耗时仍由设备决定。

## 验证

311 项自动化检查通过，包含主应用首次启动、下载前点击只消费一次、摄像头先于音效初始化、低帧率有界模拟、原识别启动与异常恢复、音源释放和预算约束。

原生 CPU Canvas 使用实际 Renderer.draw、移动人物多边形与头部、遮挡和碰撞前景、连续烟花，在 15/24 FPS 下验证四种扁平花形：最高 327 个粒子（预算 420）；长白条探测候选为零，最大白色连通跨度 9 个设备像素。它不是 iOS GPU 实机测试，手机尾段仍需复看。

60 FPS 模拟中，四种花形平均发射间隔由 2.41/3.35/3.01/2.91 秒变为 1.43/2.09/1.82/1.74 秒。保留整组自然散射和交错出生时间。

三种风格的烟花与雨声均用实际音效类、原音频和粒子模拟离线渲染，有限值、无削波、结束归零；保留试听文件。没有实际听辨最终混音，不能代替手机主观试听或硬件延迟测量。

用户录屏与人物截图只保留本地分析，未加入公开源码或部署包。原表情模型、阈值、人物和手部几何不变。v75 完整独立归档保留，v76 另存源码与部署包。
