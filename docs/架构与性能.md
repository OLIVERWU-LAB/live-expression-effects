# 架构与性能

## 输入与状态

摄像头画面留在本机。原生视频负责显示；人脸任务在独立 Worker 运行，人物分割／手部任务在辅助 Worker 运行。每个通道最多一帧在途，防止推理积压。主线程依据稳定后的笑容强度控制中性、雨滴与烟花状态，并提供锁定播放辅助检查。

原有表情模型、阈值、480 像素人脸输入、320 像素辅助输入及全身置信度遮罩保持。辅助通道至少间隔180ms；人脸按推理耗时采样。短暂异常跳过，持续异常自动恢复，迟到线程结果与图像帧通过身份和帧号隔离，不让旧结果覆盖当前会话。首次点击摄像头的意图在模块加载前由内联入口保留。

## 模拟、碰撞与绘制

粒子更新与显示分离，以速度、重力、阻力和实际运动轨迹构造射线及拖尾。头部椭圆包围补足头发边缘，人物置信度遮罩和手部几何参与碰撞。雨滴碰撞后产生有限数量的圆形水花，短时间内消失，不递归分裂。

扁平烟花发射前预测五个真实载星的位置，按屏幕与头部空间安排整组，保持后续射线的径向结构；二次绽放只继承有上限的轻微惯性。装饰环保持人物后景并绕过碰撞。移动人物明显占据预留空间时重新选择下一发，不跳移半朵花。

礼物采用离线烘焙图集，不在浏览器逐组件执行三维材质和网格渲染；每次旋转选择一个完整姿态，避免多姿态透明混合引起圆环／S管残影。两张图集包含糖果与柔彩糖果，逐发随机。写实保留人物反光，礼物与扁平只保留碰撞。

## 预算与 ROI

手机初始最多420粒子、约55万画布像素，低核设备最多300粒子、约36万像素，DPR上限1.35；持续高绘制开销才降低预算，最低150粒子。烟花活动期间不切换到破坏当前整朵结构的预算；降低细节时按每个子花和圆周层级分配，不只保留先生成的几个花。

背景暂停视频及推理，回到前台自动接续；首页不绘制特效。原生视频直接叠加扁平／礼物，避免每帧额外全屏复制。人物遮罩、颜色及纹理复用，拖尾采样、图集、声源数量均有上限。音效先加载解码，播放时不重新下载／解码；声源由视觉事件和音频时钟调度，旧事件不积压补播。

## 资源口径

全套静态资源约16.1 MB，包含SIMD与非SIMD运行库；浏览器按兼容性选择其一，不会为了首个人脸结果同时下载两套WASM。八个识别文件原始共31,396,219 B，无损压缩后15,291,599 B，减少约51.3%；重新以gzip等级9压缩没有进一步减少字节。解压后逐项校验长度与SHA-256，模型内容与恢复验收后的版本一致。

人脸首次初始化路径四个压缩文件共6,320,668 B，身体和手部另计；这不是整个首次页面的下载总量。两张WebP图集共419,360 B；五段音频共119,054 B。旧源码中的约59.9 MB冗余文件原本未全部在线下载，删除它们不等同于首屏减少59.9 MB。

正式入口不携带用户可见版本号、诊断导出面板或历史样式挑选页。模块内容标识仅用于缓存一致性，避免发布后新旧文件混用。构建按依赖清单复制，拒绝覆盖源目录；工具会检查运行目录没有未列入的额外文件。

## 验证范围

当前自动化检查覆盖真实应用模块的模拟浏览器启动、首次点击、Worker恢复、表情状态、人物碰撞、音频就绪、粒子预算及完整花型，以及解压完整性和实际WASM编译。另有原生CPU Canvas与离线Web Audio验证，历史真人反馈已用于恢复识别并调整手机表现。

本次最终整理没有在用户设备上重新执行摄像头、iOS GPU、温升或全链路延迟测量。不能把模拟测试写成所有手机固定帧率承诺，也不能用资源大小代替实际内存和推理成本。
