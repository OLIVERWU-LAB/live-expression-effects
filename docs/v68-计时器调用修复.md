# v68 · 计时器调用修复

根因：v65 的 VisionSession 构造函数直接保存 setTimeout / clearTimeout，随后以 this.setTimer / this.clearTimer 调用，把原生 Window API 的接收者变成 VisionSession。Chrome 抛出 Illegal invocation。start() 最前面的清理计时器发生在状态更新和创建 Worker 之前，因此诊断保留 phase=idle、workerCreated=false。上一轮将识别启动移到界面显示之前，使该错误还会阻断摄像头画面显示。上线不会消除这一代码错误。

修复只将默认计时器包装为通过 globalThis 调用，保留依赖注入能力。版本标识升为 68。烟花、雨滴的视觉与物理参数不变。

新增带浏览器原生 API 接收者校验的回归：修复前原样复现 Illegal invocation；修复后检查启动、帧完成、自动重试、暂停恢复、重启与销毁。实际 app 的冷启动检查也使用同一受校验环境内加载的真实 VisionSession，避免误用 Node 计时器掩盖问题。

全部 256 项自动化检查通过。当前 Work 设置禁用了浏览器控制；这些模拟检查不能作为真实 Chrome 摄像头识别已恢复的证据。已请用户在 v68 本地预览复验。

v67 源码和部署归档已核对校验值并保留；v68 独立归档。发布记录待同步线上后补充。
