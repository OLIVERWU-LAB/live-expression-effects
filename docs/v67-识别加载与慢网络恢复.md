# v67 · 识别加载与启动恢复

用户在 Chrome 中能看到摄像头，但加载提示长期不消失、笑容强度不变。最新用户诊断显示 video 正常播放，识别 phase=idle、ready=false、attempts=0、events=[]：这次本地问题发生在识别启动之前，不能归因于模型下载慢。代码中摄像头播放后的 UI 更新先于识别启动，且异常处理在有摄像头时直接返回，会掩盖这一阶段的错误。尚未取得浏览器抛出的具体异常，不能声称已确认是哪条 UI 操作抛错。

修正：取得摄像头后立即切入摄像头状态并请求识别，再更新界面。非模型异常保留在中央提示并提供重试；诊断新增启动步骤、启动异常、Worker 是否创建、暂停状态和摄像头/识别请求事件，避免再次出现无记录的永久加载。

- 人脸任务独立 Worker；首个人脸结果返回后才启动辅助 Worker。轮廓或手部初始化挂起时，表情通道继续返回结果。头部碰撞沿用真实人脸轮廓，整个人物分割由辅助通道提供。
- 不以辅助模型准备状态遮住可用的人脸识别；加载提示细分为运行库、引擎下载、人脸模型下载、模型启动、视频读取。下载显示字节进度。
- 预生成可复现 gzip 资源，用 DecompressionStream 解压，再校验完整长度和 SHA256；解压结果与原库、原模型逐字节一致。不支持解压的浏览器使用原资源。人脸启动必需文件约 13.67 MB → 6.32 MB，约减少 54%。
- 下载无进展 20 秒才中断重连；初始化进度可延长等待，最长五分钟。Cache Storage 读取有上限，写缓存不阻塞模型启动；可复用旧版已完整缓存的原始模型，避免升级后重复下载。核心 WASM 与人脸模型并行下载，汇总进度；WASM 再由本地 Blob 实例化，避免内部下载不可观测。
- 视频直接转换 ImageBitmap 失败时，复用小画布转换，不再一直重建相同失败路径。
- 失败原因在中央保留，可重新加载、复制诊断。诊断只含启动状态、设备浏览器信息及事件，不含相机图像、面部几何或模型推理输入；仅由用户主动复制，不自动发送。

验证：新增九项启动回归，包括缓存不响应、辅助 Worker 挂起、持续下载超过原 90 秒、压缩资源完整还原、实际 WASM 编译及视频取帧替代路径。使用真实 HTML 的 ID 清单执行实际 app，补测首次直接点击摄像头的冷启动，以及主动注入会话 UI 异常后识别仍被请求、错误可见且可重试；辅助初始化未就绪时人脸结果仍解除加载提示。未在用户 Chrome 或手机真机中运行摄像头推理；当前 Work 设置禁用了浏览器控制，不能把模拟检查写成真机验收。
