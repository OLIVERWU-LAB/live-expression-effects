# v74 · 手机雨滴与完整放射

针对手机截图，本轮只调整竖屏雨滴尺寸、扁平烟花的竖屏编排及细闪保留；识别模型、表情判定、声音与电脑端视觉不变。

## 根因

1. 先前的竖屏适配把五个活动散射点拉向屏幕中的五个固定位置，并改为很强的减速。靠左的炸点会因此主要往右飞，形成不自然的定向散射。
2. 首炸还按离左／右／上边缘的距离缩放，示例 390×690 靠左布局的倍率被压到约 0.055，接近消失。后来子花又被单独拉大，造成手机和电脑结构不一致。
3. 白色细闪与普通彩色装饰混在同组，被多轮抽样削减；部分点不足 1 CSS 像素。极低预算下，前几朵花又占用了后续内层与第五朵细闪的名额。

## 修正

- 宽度小于 650 CSS 像素且高大于宽时，扁平主雨滴缩至 60%，礼物缩至 75%；大小对比、颜色、高光、下落速度、发射频率保持不变。扁平碰撞后的圆形水花也同步缩小上限。写实雨滴与电脑端尺寸不变。
- 移除对五个散射点的固定目标牵引，保留原版放射矢量、减速、分层和错落时间。只在升空前为整组选择安全炸点和统一倍率；不逐个改变开花方向。接近画面边缘的自然碎点可以裁切，未死亡组件不因出界被删除。
- 竖屏细闪单独分组、保留角度分布，并设最小可见半径：白点 1.15 CSS 像素，末尾细碎点 1.35 CSS 像素。使用原本短促闪烁与消失时点，没有延长收尾。
- 最低预算下，从每圈粒子的数量分配中给所有五朵的后续内层、末尾细闪留出空间；维持 150／300／420 的既有粒子上限，没有提高预算或推迟组件生成。

- 新回归检查覆盖手机雨滴与电脑尺寸的精确比例、雨滴数量与速度、原始放射矢量与时间未被改变、安全炸点、三档预算及 60／24Hz 步进下五朵完整内层和细闪、自然生命期与无排队出生。
- 使用上一版独立源码归档与当前代码进行原生 Canvas 对比。四种扁平花型的 48 个电脑时点、两种电脑雨滴画面，共 50 个像素缓冲完全一致。
- 保留 390×690 竖屏逐帧对比及雨滴对比，确认首炸方向、尺寸和末尾亮点。原生 CPU Canvas 校验不等同于真实手机浏览器 FPS，也不能替代真人摄像头体验。
