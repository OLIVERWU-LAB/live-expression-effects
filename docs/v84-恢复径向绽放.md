# v84 · 恢复径向绽放

## 原因与修改

扁平二次绽放原先把载星的全部剩余速度直接加给每条子射线。虽然展开向量原本按圆周分布，但一整朵花被同一个较大速度推动，部分射线甚至无法朝相反方向移动，出现朝同一侧扫出的观感。空间较窄时这个偏向更容易看出来。

仅修改二次绽放的惯性继承：保留载星剩余速度的最多12%，并再将整朵花的共同漂移限制为22×局部尺度的速度上限。各射线相对中心的原始径向向量保持，出生位置继续取载星的真实位置；保留轻微漂移衔接，不出现突然跳位。

v83整组选位、五个二次绽放中心、头部避让、随机布局、手机／电脑适配保持原样。三种花的数量、颜色、头部大小、寿命、拖尾长度、错开时间和发射间隔不变。声音、雨滴、人物与表情识别不变，没有新增媒体资产或额外计算流程。

## 验证

330项检查通过。新增覆盖三种样式、三档尺度、15套随机种子、每次五个载星：共同漂移不超过载星速度12%及局部尺度上限；每条射线保持原来的相对展开向量，子花出生点／寿命／颜色／大小／拖尾参数完全一致；快速载星也不能把整朵花带往一边。

与v83对比，144组电脑／手机布局的结果逐字段完全一致。三档尺度×24套随机种子×每朵五个二次绽放的方向检查中，每个样式各360朵：主射线缺少某个象限的数量从同心58、星冠63、锦簇30，降至三者均为0；平均整体方向偏置约从0.49–0.52降到0.12–0.13。该检查分析真实生成速度，不等于实机观感评分。

实际Renderer对照包括手机与电脑、移动人物轮廓、遮挡与碰撞。手机390×690、15/24FPS连续发射检查中，三种样式均未超过420粒子，未检出长白条候选。以上为原生CPU Canvas绘制及世界模拟，未在用户手机上调用摄像头验证。

v83完整源码、匹配部署包与提交标识已保留；v84另存完整独立版本及校验。
